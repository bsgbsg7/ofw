## 2. 根因分析

### 2.1 正交性正则化有效但不够

BCE+Ortho 训练成功将 Q 条件数从 10^5 降到 ~1.5, L_ortho=0.001 表明 Q 已接近酉矩阵。**但 BER 没有改善** — 说明问题不在 Q 的正交性。

### 2.2 为什么 BER 卡在 0.26?

#### 原因 1: 架构信息瓶颈

```
CIR (l_tot, 32 snapshots) 
  → Conv1D + GRU (处理 delay 维)
  → GlobalAveragePooling  ← 瓶颈! 把所有 delay 信息压成 1 个向量
  → Dense(1024) → Dense(64×64+64)
```

从 1024 维向量生成 4096 个复数 Q 参数 + 64 个 q 参数，**每个参数只能得到 ~0.25 个隐层神经元的控制**，信息密度严重不足。

#### 原因 2: 训练 SNR 范围太宽

SNR ∈ [0, 15]dB 意味着:
- 0dB: 信号功率 = 噪声功率, 任何通信都极其困难
- 模型被迫在极低 SNR 上浪费大量容量, 无法专注于中高 SNR 的波形优化

#### 原因 3: 64×64 Q 的自由度远超任务所需

TDM/OFDM/OTFS 三种目标变换只需控制很少的参数:
- TDM: Q = I (无自由参数)
- OFDM: Q = IDFT (无自由参数)  
- OTFS: 在 64×64 酉群上的一个特定点

但模型有 4096 个自由参数来逼近这几个点 — 过度参数化导致训练困难。

#### 原因 4: Doppler 信息可能未被有效利用

CIR 的 32 个时间快照输入到 Time-Path (Conv1D cross-snapshot), 但 Time-Path 输出最终被 GlobalAveragePooled 到 64 维。Doppler 信息在压缩中丢失。

## 3. 改进方向

### 短期可行

| 优先级 | 改进 | 预期效果 |
|:---|:---|:---|
| 🔴高 | **提升训练SNR**: [5,20]dB, 去掉0dB极低SNR | BER更快收敛 |
| 🔴高 | **减小Q到32×32**: 回到已验证的配置规模 | BER可能降到0.05-0.10 |
| 🟡中 | **FFT=32, BW=20MHz**: 保持OOK分辨率, 减少参数 | delay bins=6, Q只有1024参数 |
| 🟡中 | **增加GRU层数**: 1→2层, 提升delay维建模能力 | 更强的多径表征 |

### 中期需架构改动

| 优先级 | 改进 | 预期效果 |
|:---|:---|:---|
| 🟡中 | **替换GlobalAvgPool**: 用attention或structured pooling | 保留空间信息 |
| 🟢低 | **分阶段训练**: 先低速, 后引入高速 | 渐进式学习Doppler |
| 🟢低 | **辅助loss**: dist(Q, IDFT)对低速加权 | 引导OFDM学习 |

---

## 4. 结论

**28GHz + 64×64 Q + 16 符号的配置超出了当前架构的训练能力。** 核心瓶颈不是 loss 函数，而是:

1. 架构信息瓶颈 — 1024维→4096参数的映射过于稀疏
2. 训练 SNR 范围太宽 — 模型在 0dB 上浪费容量
3. Q 过度参数化 — 4096 参数远多于任务所需

**建议**: 回到 FFT_SIZE=32, 保持 28GHz 和 10MHz 带宽, 用 16 符号确保 Doppler 分辨率。这样 Q 只有 1024 参数, 与已验证的 3.5GHz 配置相同规模。
